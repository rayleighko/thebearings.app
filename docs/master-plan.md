# Bearings AX Master Plan — "본업에 집중하는 사람들의 투자 관리"

> v0.1 · 2026-07-10 · SoT 후보: `docs/master-plan.md`로 레포에 커밋 권장
> 법률 자문 아님 — 규제 항목은 리서치 기반이며, 출시 전 로펌 검토 + 금융규제·법령해석포털(better.fsc.go.kr) 익명 질의 권장

## 1. 비전 선언

**"본업이 있는 사람이 전문가의 전략으로, 자기 성향에 맞게, 모든 결정은 스스로 내리면서 포트폴리오를 관리하게 한다. AI는 실행자가 아니라 브리핑하는 참모다."**

- 사용자 여정: 성향 진단 → 전략 템플릿 선택 → 자산 연결(단계적) → 리밸런싱 프리뷰 수신 → **사용자 승인** → 실행 → 복기·학습
- AI의 역할: 시장 상황 코멘트/팁/교육 + 리밸런싱 프리뷰의 "이유" 설명. **개별 종목 매수/매도/비중 지시는 절대 출력하지 않음** (기존 3-layer 안전필터 재활용)
- 핵심 정체성: **AX 투자 관리** — AI가 서비스 내부 엔진이면서, 사용자도 직접 모델을 선택·활용

## 2. 법적 경계 설계 (Guardrail Architecture)

리서치 결론을 제품 불변식(invariant)으로 변환한다. 각 가드레일은 코드 레벨 강제 대상이며, 해당 이슈(백로그 G-시리즈)와 1:1 매핑된다.

| ID | 불변식 | 근거 (요약) | 리스크 등급 |
|---|---|---|---|
| **G1** | 주문은 매 건 명시적 승인. 승인 유효시간 짧게(분 단위). 프리뷰=실제 주문 완전 일치(서비스가 가격·수량 사후 조정 금지). **"다음부터 자동 실행" 옵션 코드에서 원천 금지** | 금융위 유권해석: 자동매매 연동 = 무등록 투자일임업(형사처벌). 매 건 승인 = 투자판단 미이전 논리. 단 직접 유권해석 부재 — 법령해석 질의 필요 | 최고 |
| **G2** | 전략 템플릿·시장 코멘트를 유료 제공하려면 **유사투자자문업 신고**(개인 가능, 사전교육 이수) 선행. 1:1 상담·유저 계좌 기반 개별화 코멘트·양방향 채팅 금지(2024.8 개정법상 투자자문업 등록 영역) | 대법원 2018도4413: 템플릿/설정값 제공 = 유사투자자문. AI 출력도 내용 기준으로 동일 판단 | 높음 |
| **G3** | V1은 **단일 증권사 연결**. 복수 증권사 잔고 통합 화면 금지(마이데이터 유사행위). 계좌 데이터는 세션성 조회 위주, 서버 축적 최소화 | 마이데이터 허가 = 자본금 5억+물적설비 — 1인 비현실적 | 높음 |
| **G4** | 수익모델은 **정액 구독만**. 거래량/거래액 연동 수수료, 계좌 개설 리퍼럴 금지 | 거래 연동 수수료 = 무인가 투자중개업 실질 인정 요소 | 중 |
| **G5** | **주문 호출은 클라이언트 사이드** — 사용자 API 키/Secret이 우리 서버를 경유·저장되지 않는 구조를 기본값으로 설계 (아래 §3.3). KIS는 핀테크 제휴 불가 명시 → 약관 리스크의 현실적 완화책 | "소프트웨어 도구 제공자" 방어 논리 (2018도4413 도구 법리 정합). 토스/키움 약관 원문 확인은 열린 항목 | 중 |
| **G6** | 모든 AI 출력에 "AI 생성 · 투자권유/자문 아님 · 최종 판단은 사용자" 고지. 안전필터 트리거 로그 보존 | 금융분야 AI 가이드라인(2026 Q1 시행 예정): 사전 고지·보조수단성 — 핀테크에도 적용 가능 | 중 |

**확장 트리거**: 자동실행·개별화 추천·다계좌를 원하는 시점 = ①투자자문업 등록 → ②일임업 등록+코스콤 RA 테스트베드(약 7개월) → ③혁신금융서비스 지정. 전부 법인화 전제 — **그 전까지는 위 6개가 제품의 헌법**.

### 3.2 Model-Agnostic AI 레이어 ("코드 변경 없이 모델 추가")

핵심은 **모델을 코드가 아니라 데이터로 취급**하는 것.

- **Model Registry (DB 테이블)**: `model_id, provider, api_name, tier(free/pro/byok), max_tokens, price_per_mtok, enabled, released_at`. 새 모델 출시 → **row 추가만으로 사용자 선택지에 등장**. 코드 배포 불필요.
- **Provider Adapter 인터페이스**: `complete(messages, opts) → stream`. 어댑터는 provider당 1개(Anthropic/OpenAI/…), 신규 provider 추가 시에만 코드 작업. LangChain 도입은 **보류** — 1인 유지보수 기준 추상화 비용이 이득보다 크고, Vercel AI SDK 정도의 얇은 레이어 + 자체 어댑터가 현 수준에 맞음 (ADR로 기록, 아래 백로그 A-2).
- **Prompt as Config**: 시스템 프롬프트·페르소나(Aurora/Vesper)·안전 규칙을 버전 관리되는 설정 파일(`prompts/*.yaml` + DB 오버라이드)로 분리. 모델 바뀌어도 프롬프트만 튜닝.
- **과금 3단**: ① Free = 룰베이스 템플릿 + 일 1회 배치 생성 코멘트(전 사용자 공유 — 한계비용 0, 기존 Zero-cost 전략 유지) ② Pro = 우리 키로 상위 모델 + 개인화 아닌 "선택 지표 심층 해설" ③ **BYOK = 사용자 본인 API 키 등록 → 무료 사용자도 자비로 최상위 모델 사용** (우리 비용 0, "무료로도 충분히 즐긴다" 요구 충족)
- **파인튜닝은 명시적 보류**: 학습 데이터 없음, 모델 세대교체 주기 < 파인튜닝 유지보수 주기, Option B 특성상 스타일보다 사실성이 중요 → RAG + 프롬프트로 충분. 재검토 조건: 안전필터 오탐률이 프롬프트로 안 잡힐 때 분류기(Layer 2)만 소형 파인튜닝 후보.

### 3.3 자산 연결과 주문 실행 (G3·G5 구현)

- **L1 (수동/CSV)**: 보유내역 붙여넣기·CSV 업로드. 시장 중립, 법적 리스크 0. Bearings 분석기와 공유.
- **L2 (읽기 연결)**: 사용자가 증권사에서 직접 발급한 키를 **브라우저(IndexedDB, 암호화) 또는 로컬 실행기에 저장**. 조회 호출도 클라이언트에서 직접. 서버는 파생 요약(비중 %, 종목 수)만 선택적으로 수신 — G3 세션성 원칙.
- **L4 (승인 후 실행)**: Rebalance Engine이 프리뷰 생성(서버, 시세+전략만 필요) → 클라이언트가 프리뷰를 받아 사용자 승인 → **Order Executor가 기기에서 증권사 API 직접 호출**. 멱등성 키 + 승인-주문 해시 일치 검증 + 감사 로그(클라이언트 서명 포함).
- CORS 등으로 브라우저 직접 호출이 막히는 증권사 API의 경우: 로컬 실행기(Tauri/Electron 트레이 앱 또는 CLI)로 대체 — ADR 대상. **어느 경우든 키는 서버에 오지 않는다.**
- 1차 증권사 선정: KIS(문서·커뮤니티 최다, 모의투자 제공) vs 토스(사용자 규모, 신규 API). 모의투자 지원하는 **KIS로 개발, 토스는 사용자 수요 보고** — ADR 대상.

### 3.4 Indicator Hub (초보~전문가 공용 지표 대시보드)

기존 ECOS/FRED 파이프라인 + DB-first ingest 원칙(founder-log 2026-06-12 결정) 그대로 확장:

| 지표 | 소스 | 비고 |
|---|---|---|
| FOMC 성명·의사록·점도표 | Fed 공식 (federalreserve.gov) + FRED | 의사록 전문은 RAG 인제스트 → AI 요약 코멘트 |
| Fear & Greed | CNN 지수는 재배포 제약 → **자체 합성** (VIX, put/call, 모멘텀 등 공개 원료로 자체 지수) | "누구 것도 베끼지 않는 우리 지표"가 브랜드 자산 |
| 버핏 지수 | Wilshire 5000/GDP — FRED 무료 | 과열 판정의 대표 지표 |
| 금리·물가·고용 코어 | ECOS + FRED (기존) | 이미 구현 |
| 레짐 판정 | 기존 Bearings regime engine | **과열 추론 = composite + 레짐 + 위 지표의 규칙 기반 종합 + AI는 '해설'만** — 예측을 팔지 않고 현재 상태의 해석을 판다 (Option B 정합) |

각 지표에 3단 표기: 원값 → 역사적 percentile → 한 줄 해설(초보용). 전문가는 원값·시계열, 초보는 percentile·해설을 보는 동일 화면.

### 3.5 성향 진단 (기존 자산 재활용 — 확인 결과)

**재활용 가능, 거의 완성 상태.** 레포 실측(문서 기준): 24스텝 SurveyModal(Q0 + GL-RTS 13문항 + 사실문항 10) 구현 완료, `user_investment_profile` 테이블 존재, PostHog 이벤트 스펙 작성 완료(계측은 미심기), 한국어 번안(gl-rts-13-korean.md) 완료. 남은 것: `scoreGlRts`/`classifyBit` 스코어링 함수(로드맵 S3 "Task 5 Green" — 직접 타이핑 예정이던 것)와 결과 카드 UI. **주기적 재검증**은 founder-log의 분기 재퀴즈 결정 + `profile_snapshot` 타임라인 설계가 이미 있어 그대로 백로그화한다. 성향 결과는 "전략 템플릿 필터"로 연결 — 단 "당신 성향엔 이 전략" 처방이 아니라 "이 성향 사용자들이 일반적으로 검토하는 카테고리" 프레임(G2).

### 3.6 교육 + 게이미피케이션

원칙: **학습은 게이미피케이션 OK, 거래는 역게임화** — FCA 연구(트레이딩 앱 게임화가 거래빈도·위험자산 비중 증가) 근거로 이 비대칭이 브랜드 정체성.

- 학습 트랙: 교육 모듈 → 퀴즈 → 배지/레벨/스트릭 (v3 learning-cycle 비전 재활용, soft gate는 유료 기능 잠금이 아니라 "이해 확인" 프레임)
- 초보 여정: 성향 진단 → 내 성향 해설 → 관련 개념 모듈(분산, 비용, 손실한계) → 퀴즈 → 전략 템플릿 열람 자격
- 거래 측: 컨페티·수익률 리더보드·연속 매매 보상 **금지** (기존 AD-8 anti-pattern 유지)

### 3.7 RAG 설계 (현 수준에 맞게)

- 스토어: Supabase pgvector (새 인프라 0)
- 인제스트: FOMC 의사록/성명(영→한 요약 파이프라인), 지표 해설 문서(자체 작성), 교육 모듈 원고. **사용자 데이터는 RAG에 넣지 않음** (G2·G3)
- 파이프라인: cron(기존) → fetch → chunk → embed → upsert. 검색: 코멘트 생성 시 top-k 컨텍스트 주입
- 평가: golden question set 20개로 회귀 테스트 (환각 검증 — 인용 없는 수치 출력 금지 규칙)

## 4. 실무 방식 채택 — 개발 프로세스

선택 확정: **GitHub Issues + Projects** (레포: 기존 cohort).

- **라벨 체계**: `type:*`(feat/fix/docs/adr/legal/infra) · `area:*`(guardrail/ai-gateway/indicator/profile/education/rebalance/analytics/growth) · `milestone` = 페이즈 · `priority:P0~P2`
- **Projects 보드**: 뷰 3개 — ① Roadmap(타임라인, milestone 기준) ② Kanban(Now/Next/Later) ③ Table(라벨 필터). "시계열로 한눈에"는 Projects의 Roadmap 뷰 + 아래 HTML 시각화 이중화
- **운영 리추얼**: 주 1회 15분 — PostHog 지표 확인 → 이슈 상태 갱신 → 다음 주 P0 1~2개 선언. 모든 결정은 founder-interview-log.md에 계속 축적(이미 좋은 관행)
- **PR 규율**: 기존 Sub-agent Workflow Discipline 유지(단일 커밋 스코프, tsc 게이트, no --no-verify). 이슈 없이 PR 없음 — "이슈가 스펙, PR이 구현"
- **백오피스는 만들지 않는다(지금은)**: 모니터링 = PostHog + Sentry + GitHub Projects로 충분. 서비스 내 admin 대시보드는 유료 사용자 발생 후(운영 데이터가 생겨야 화면 설계가 가능). 단, 이슈로는 Later에 등록

## 5. 로드맵 (마일스톤 = GitHub Milestone과 1:1)

시간은 "취업 준비 병행, 주 상한" 전제의 상대 추정. 각 마일스톤은 출하 가능한 수직 슬라이스.

| 마일스톤 | 내용 | 출하물 | 기간(추정) |
|---|---|---|---|
| **M0 Foundation** | 리네이밍 정리, CI, 라벨/보드 세팅, 법령해석 질의 발송, 유사투자자문업 신고 조사 | 거버넌스 가동 | 1–2주 |
| **M1 Bearings Wedge** | regime 분석기 실사용 완성 + PMF 계측 + 공유 카드 | 첫 활성 사용자 | 2–3주 |
| **M2 Indicator Hub + AI 코멘트** | 지표 대시보드(FOMC/버핏/자체 F&G) + LLM Gateway v0 + RAG v0 + 일일 배치 코멘트 | 재방문 이유 | 3–4주 |
| **M3 Profile + Learn** | GL-RTS 완성(scoring+결과 카드) + 분기 재검증 + 교육 모듈 3개 + 퀴즈 | 초보 온보딩 | 3–4주 |
| **M4 Portfolio L1–L2** | 수동/CSV 포트폴리오 + KIS 읽기 연결(클라이언트 사이드) + drift 뷰 | "내 자산" 화면 | 4주+ |
| **M5 Rebalance L4** | 전략 템플릿 × 승인형 실행(모의투자 먼저) + 감사 로그 | 핵심 가치 실증 | 4주+ |
| **M6 Monetize** | 유사투자자문업 신고 완료 전제 → Pro 구독 + BYOK 모델 티어 | 첫 매출 | 2주 |

순서 논리: 수익화(M6)는 신고 완료와 M2~M3 가치 증명 뒤. M4–M5는 법령해석 회신·약관 확인(M0의 legal 이슈) 결과에 **조건부** — 회신이 부정적이면 L4는 모의투자 전용으로 피벗하고 M5를 "리밸런싱 시뮬레이터"로 축소(이것도 충분히 팔리는 제품).

## 6. 리스크 레지스터 (요약)

1. **법령해석 리스크**: 1-tap 승인 구조의 직접 유권해석 부재 → M0에서 익명 질의, 회신 전 L4 코드는 모의투자 한정
2. **약관 리스크**: 토스/키움 약관 원문 미확인 → M0 확인 이슈, KIS는 모의투자로 우회 개발
3. **범위 폭주 리스크**: 이 비전은 팀 규모 비전이다 — 마일스톤 밖 아이디어는 전부 이슈로만 받고 `later` 라벨 (이 문서가 방파제)
4. **AI 출력 사고**: 개별 추천이 새는 순간 G2 붕괴 → 안전필터 회귀 테스트를 CI 게이트로 (기존 50+ 케이스 자산 재활용)
5. **번아웃**: 주간 상한 초과 2주 연속이면 마일스톤 재협상 — 이것도 리추얼의 체크 항목
